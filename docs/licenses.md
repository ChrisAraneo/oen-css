# Licenses

oen-css is a derivative work of Bulma. Both are MIT, and MIT requires the
copyright and permission notice to be included in every copy and substantial
portion of the software. `src/licenses/` is where that obligation is turned
into files.

## What ships

| File                     | Content                                       |
| ------------------------ | --------------------------------------------- |
| `oen.css`                | the stylesheet, with the attribution banner   |
| `oen.min.css`            | the same, minified                            |
| `LICENSE`                | our license, kept in the repository           |
| `LICENSE-bulma`          | Bulma's license, verbatim from `node_modules` |
| `THIRD_PARTY_NOTICES.md` | generated — see below                         |

Every one of them sits at the repository root, which is the package root: the
published tarball has no `dist/` directory. `package.json` lists all five in
`files`, and npm adds `package.json` and `README.md` on its own. Both
stylesheets additionally carry the attribution banner inside them, which
names `LICENSE-bulma` — see [BANNER.md](./BANNER.md).

Bulma's license is copied from `node_modules/bulma/LICENSE` at build time
rather than committed, so it always matches the version that was compiled.

## The generated notices

[`format-third-party-notices.ts`](../src/licenses/format-third-party-notices.ts)
produces `THIRD_PARTY_NOTICES.md` with three parts:

1. a statement of what oen-css is — Bulma's Sass sources compiled with
   `--bulma-*` re-namespaced to `--oen-*` — and that our own license does not
   replace the notices below,
2. Bulma's section: version, project and source URLs, and the full license
   text in a fenced block,
3. a section per notice found embedded in the compiled stylesheet.

The third part is generated by reading the license comments back out of the
built `oen.css`, not from a hand-kept list. It therefore always matches
the artifact: if Bulma starts or stops vendoring something, the notices change
on the next build.

Because the file is generated, it is in `.prettierignore`: Prettier would
otherwise reformat what the generator writes.

## minireset.css

Today that third section has exactly one entry. Bulma vendors minireset.css
(MIT, same author) into its base styles together with its own `/*! … */`
comment. That comment survives compilation and minification, so it reaches
users inside the stylesheet itself. It is documented because it is part of what the package
distributes.

## What verify enforces

Three of the fourteen checks are about licensing:

| Check                                            | Asserts                                                                                |
| ------------------------------------------------ | -------------------------------------------------------------------------------------- |
| `Bulma's license ships verbatim`                 | the copyright line appears in both `LICENSE-bulma` and the notices                     |
| `own license ships with the package`             | `LICENSE` is the MIT notice, and its copyright line is reported                        |
| `notices embedded by Bulma survive minification` | every notice found in `oen.css` is also in `oen.min.css` and documented in the notices |

The third check matters most. Minification is the step that would strip a
comment without reporting it, so clean-css is configured to keep all of them.
If Bulma drops a vendored notice, the check fails with a message saying to
remove it deliberately. The failure asks for a decision, not for a quick fix.
